### Removed

- **Wan 2.2 model family retired from the product.** Oelala now serves
  MiniMax-H3 (leading/default video model) and LTX-2.3 (second choice) only.
- Deleted the Wan2.2 generation adapters:
  `src/backend/generation/adapters/cloud/wan22_i2v.py`,
  `src/backend/generation/adapters/cloud/wan22_t2v.py`,
  `src/backend/generation/adapters/local/i2v_wan22.py`,
  `src/backend/generation/adapters/local/i2v_wan22_base.py`,
  `src/backend/generation/adapters/local/i2v_wan22_lightning.py`,
  `src/backend/generation/adapters/local/t2v_wan22.py`,
  `src/backend/generation/adapters/local/v2v.py` (V2V style transfer was
  Wan2.2-only), plus their registrations in the adapter `__init__.py`
  files, `generation/factory.py`, and the `generation` package exports.
- Removed the retired `oelala-wan22` RunPod endpoint (id `x2x496ymkidl3m`)
  via the RunPod GraphQL API and deleted the worker image + deploy script in
  `deploy/runpod/` together with `tests/test_runpod_handler.py`.
- Deleted the dead local Wan2.2 ComfyUI workflow JSONs
  (`workflows/ImageToVideo/wan22_*.json`, `workflows/VideoExtension/extend_video_wan22.json`,
  `scripts/tested_workflows/Text2video/wan22_t2v_frigate_safe.json`) and their
  entries in `workflows/registry.json`.
- Removed Wan2.2 from `src/backend/generation/compute_backends.py`,
  `compute_backends.json(.example)`, the `runpod_defaults.py` wan22 profile,
  `.env.example` compute-node families, and the factory presets in
  `tool_profiles_api.py` (LTX-2.3 preset kept).
- Removed Wan2.2 as a selectable video model from the frontend tools
  (Text-to-Video, Image-to-Video, legacy VideoGenerator, PresetSelector,
  AdminComputeTab) and the wan22-only Video-to-Video tool; model lists now
  lead with MiniMax-H3, LTX-2.3 second.
- Removed router frame normalization for the Wan2.2 4k+1 grid
  (`normalize_frame_count` / `GenerationRouter.normalize_frames`) and the
  wan22-only `high_noise_steps` / `shift` request fields.
- Deleted wan22-only tests: `tests/test_local_video_adapters.py`,
  `tests/test_wan2_setup.py`, the Wan22 cloud/local/phase6 test classes, and
  the wan22 frame-count tests in `tests/test_generation_core.py`.

### Changed

- Requests naming the retired family now fail clearly instead of silently
  falling back: the generation router raises a dedicated "Wan 2.2 has been
  retired" error (HTTP 400 via both the v2 API and the v1 compat layer)
  naming MiniMax-H3 (leading) and LTX-2.3 (alternative).
- MiniMax-H3 is the default/leading video choice in every model list and
  fallback; LTX-2.3 is second. Persisted tool profiles still carrying
  wan22 modes coerce to MiniMax-H3 on load.
- Model catalog regenerated (`docs/model_catalog.yaml`,
  `docs/MODEL_CATALOG.md`, 245 entries): the `runpod_wan22_worker` source is
  gone from `scripts/build_model_catalog.py`.
- `docs/GENERATION_MODES_TREE.md` updated: Wan2.2 sections removed, H3
  first, LTX-2.3 second. Wan2.2 LoRA entries in `docs/lora_registry.yaml`
  are deliberately kept and marked legacy/parked for a possible future
  open-weight "Wan 3" (weights stay on disk; no weights were deleted).
