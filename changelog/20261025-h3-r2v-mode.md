### Added

- **MiniMax-H3 R2V (Reference-to-Video) generation mode** — video2video character swap on the REF2VA checkpoint (separate weights from FL2VA):
  - Workflow builders `build_{cloud,local}_minimax_h3_r2v_workflow()` in `comfyui_client.py`: `MiniMaxH3ReferenceToVideo` conditioning node with 1 source video (`LoadVideo` + `GetVideoComponents` → frames + soundtrack) and up to 4 reference images; shared sampler tail with T2V/I2V; dedicated `MINIMAX_H3_REF2V_TURBO_PRESETS` ("draft" = ref2v 4-step distill, "full" = base 20 steps).
  - Adapters `minimax-h3-local-r2v` (Windows-PC ComfyUI, uploads video + refs itself) and `minimax-h3-cloud-r2v` (RunPod; base64 `videos` map rides along in the job input), registered in the factory.
  - RunPod H3 worker: ref2va UNET + ref2v turbo LoRA added to the on-demand model registry; `save_input_videos()` stores job input videos (magic-byte container sniffing) and the handler rewrites media references in the workflow.
  - Backend `_submit_to_runpod()` accepts an optional `videos` dict next to `images`.
  - Frontend `VideoToVideoTool.jsx` (video + up to 4 reference images, prompt, draft/full, LoRA picker) registered in the tool navigation.
  - Offline workflow-builder tests in `tests/test_comfyui_minimax_h3_r2v.py` (69 offline tests green) and a live GPU test `tests/gpu/test_minimax_h3_r2v_live.py` — verified end-to-end on the Windows-PC ComfyUI (ref2va checkpoint + ref2v turbo LoRA provisioned there, 39-frame draft swap rendered and retrieved in ~80s).
